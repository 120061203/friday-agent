# 系統當機 / 服務中斷處理流程

## 適用情境
內部系統無法開啟、回應逾時，或員工回報服務中斷、藍屏當機。

## 排查步驟
1. 確認是單一使用者還是多人受影響，範圍決定事件等級。
2. 檢查服務健康檢查（health check）與最近的部署/變更紀錄，優先懷疑最近一次變更。
3. 查看資源監控（CPU / Memory / Disk），確認是否資源耗盡。
4. 檢查相依服務（資料庫、認證服務、外部 API）是否正常。
5. 若判定需要重啟服務，務必先走 Guardrail / 變更審核，不可直接於正式環境操作。

## 常見原因與處理
- 最近部署造成回歸 → 優先評估回滾（rollback）。
- 資源耗盡 → 短期先擴充資源，長期追查記憶體洩漏或流量異常。
- 相依服務中斷 → 通報對應團隊，同步對外公告服務狀態。

## 升級條件
影響全球多個辦公室或超過 50 人回報，視為 P1 事件，立即啟動事件應變流程並知會主管。
